This is an important placement topic because MAC, Ethernet, frames, collision domains, and switching all connect here.

2.1What does the Data Link layer do?

The Data Link layer provides node-to-node delivery (one hop). Its main responsibilities:

  • Framing: wrapping the packet with a header and trailer
  • MAC addressing
  • Error detection (FCS/CRC)
  • Medium access control (who may transmit on a shared medium)
  • Flow control in some link-layer protocols
Network Layer → IP packetData Link Layer → Ethernet FramePhysical Layer → Bits

Two sublayers

  • DATA LINK
    • LLC (Logical Link Control) interface between Network layer and MAC
    • MAC (Media Access Control) MAC addressing · controlling access to the shared medium · frame-related functions

CSMA/CD and CSMA/CA operate at the MAC sublayer.

Framing methods + Added

How does the receiver know where a frame starts and ends? Character count (rarely used), byte stuffing (flag byte; escape any flag inside the data with an ESC byte), bit stuffing (HDLC flag 01111110; after five consecutive 1s in the data, insert a 0), and physical-layer coding violations. Ethernet uses a preamble + Start Frame Delimiter plus inter-frame gaps.

2.2MAC address

A MAC address identifies a network interface at the Data Link layer. Example: 48:2A:E3:91:AB:10. It is 48 bits = 6 bytes, written as 12 hex digits.

  • First 24 bits = OUI (Organisationally Unique Identifier, the vendor) + Added
  • Last 24 bits = NIC-specific part assigned by the vendor
  • Least-significant bit of the first byte: 0 = unicast, 1 = multicast. Second-least: 0 = globally unique, 1 = locally administered (e.g. phone MAC randomisation)
  • Broadcast MAC = FF:FF:FF:FF:FF:FF
Remember

IP is used for routing between networks. MAC is used for delivery on the local link.

2.3Ethernet frame

Important fields: Destination MAC, Source MAC, Type/Length, Data, FCS. Destination comes first so a switch can start forwarding as soon as it reads 6 bytes (cut-through switching).

FCS (Frame Check Sequence) is used for error detection, using a 32-bit CRC. It detects whether the frame was corrupted in transmission; a bad frame is silently dropped (Ethernet does not retransmit, higher layers like TCP do).

+ Added · numbers to remember
  • Preamble 7 B + SFD 1 B (not counted in frame size)
  • Header 14 B (6 + 6 + 2) + FCS 4 B = 18 B overhead
  • Payload 46–1500 B → frame 64–1518 B (1522 with an 802.1Q VLAN tag)
  • MTU = 1500 B. Payload shorter than 46 B is padded.
  • Type values: 0x0800 = IPv4, 0x0806 = ARP, 0x86DD = IPv6, 0x8100 = VLAN tag

2.4Hub vs switch, and how a switch learns

A very common interview question. A hub (Layer 1) repeats the signal to all ports. A switch (Layer 2) keeps a MAC → port table and only sends the frame where it needs to go.

Try it: send frames between hosts and watch the table fill in. Toggle hub mode to compare.

The learning process, step by step

  1. A sends a frame to B. The switch sees Source MAC = A on port 1, so it learns A → Port 1.
  2. It checks the destination MAC B. If B is unknown, it floods the frame out all ports except the incoming port.
  3. When B replies, the switch learns B → Port 2.
  4. Now A → B frames are forwarded directly to port 2 only.
Classic interview line

A switch learns from the SOURCE MAC and forwards based on the DESTINATION MAC.

+ Added Entries age out (typically 300 s) so the table stays current when devices move. Broadcast frames (FF:FF…) and unknown unicast are always flooded. Switching modes: store-and-forward (receive whole frame, check FCS, then forward) vs cut-through (forward after reading destination MAC; lower latency, may pass bad frames).

2.5Collision domain vs broadcast domain

Collision domain

A region where transmitted frames can collide. All devices on a hub share one collision domain. Each switch port is generally a separate collision domain.

Broadcast domain

The group of devices that receive a Layer-2 broadcast. A router separates broadcast domains: a broadcast from Network A does not normally cross the router. VLANs also split them.
Quick memorySwitch → separates collision domainsRouter → separates broadcast domains
+ Added · counting question

"2 hubs (4 PCs each) connected to a switch, switch connected to a router" → collision domains = 2 (one per hub port on the switch) + 1 (switch–router link) = 3; broadcast domains = 1 on that side of the router. Rule: count switch/router ports in use for collision domains; count router interfaces (or VLANs) for broadcast domains.

2.6VLANs + Added

A VLAN (Virtual LAN) splits one physical switch into several logical Layer-2 networks. Each VLAN is its own broadcast domain, so traffic between VLANs needs a router (or a Layer-3 switch): "inter-VLAN routing".

  • IEEE 802.1Q inserts a 4-byte tag (12-bit VLAN ID → up to 4094 usable VLANs) into the frame.
  • Access port: belongs to one VLAN, untagged frames (to a PC).
  • Trunk port: carries many VLANs, tagged frames (switch to switch).
  • Why: security isolation (HR vs guests), smaller broadcast domains, flexible grouping without rewiring.

2.7Spanning Tree Protocol (STP) + Added

Redundant links between switches create loops. Ethernet frames have no TTL, so a broadcast circles forever: a broadcast storm, plus MAC table instability. STP (IEEE 802.1D) fixes this by logically blocking some ports so the active topology is a tree.

  1. Elect a root bridge (lowest Bridge ID = priority + MAC).
  2. Each other switch picks its root port (lowest cost path to root).
  3. Each segment picks a designated port.
  4. All other ports are blocked; they unblock if an active link fails.

Rapid STP (RSTP, 802.1w) converges in seconds instead of ~30–50 s.

3.1Why do we need medium access control?

Imagine many computers on the same shared medium (a bus, a hub, or the air). If everyone transmits whenever they want, A and B might transmit simultaneously and their signals collide. We need a rule for: when can I transmit?

  • Multiple access protocols + Added
    • Random access anyone may try
      • ALOHA (pure, slotted)
      • CSMA → CSMA/CD (Ethernet), CSMA/CA (Wi-Fi)
    • Controlled access take turns
      • Reservation · Polling · Token passing (Token Ring, FDDI)
    • Channelization split the channel
      • FDMA · TDMA · CDMA

3.2ALOHA + Added

The ancestor of CSMA: transmit whenever you have data, wait for an ACK, back off randomly if none comes.

3.3CSMA: Carrier Sense Multiple Access

  • Carrier Sense: before transmitting, ask "is someone already transmitting?"
  • Multiple Access: many devices share the same medium.

So: Listen → if free → transmit. But there is still a problem: two devices may both check at almost the same time, both see "free", both transmit, and collide (because of propagation delay). That is where CD and CA come in.

+ Added Persistence strategies: 1-persistent (send immediately when idle; Ethernet), non-persistent (if busy, wait a random time then sense again), p-persistent (if idle, send with probability p; slotted channels).

3.4CSMA/CD: Collision Detection

Historically associated with shared, half-duplex Ethernet (hubs, coax).

The device can detect "my transmission collided" (the voltage on the wire differs from what it is sending). It then stops, sends a 32-bit jam signal + Added so everyone notices, and backs off.

Binary Exponential Backoff

This is the algorithmic part to remember. After collisions, devices do not retry immediately. They choose a random backoff, and the possible range doubles after each repeated collision. This reduces the chance the same devices collide again.

Exact rule + AddedAfter the n-th collision: pick K ∈ {0, 1, …, 2^min(n,10) − 1}Wait K × slot time (512 bit-times = 51.2 µs at 10 Mbps)Give up after 16 attempts

Minimum frame size + Added

A sender must still be transmitting when news of a collision gets back to it, otherwise it cannot detect the collision. So:

ConditionTt ≥ 2 × Tp  ⇒  L_min = 2 × Tp × R

Classic Ethernet: 10 Mbps × 51.2 µs = 512 bits = 64 bytes minimum frame. That is why short payloads are padded to 46 bytes.

3.5CSMA/CA: Collision Avoidance

Used primarily in Wi-Fi (IEEE 802.11). Why not detect collisions? In wireless, the transmitter's own signal is far stronger than anything it could hear from others, so detecting a collision while transmitting is impractical. Wi-Fi tries to avoid collisions before they happen, and uses ACKs to learn about failures.

+ Added Wi-Fi timing: wait DIFS before contending, SIFS (shorter) before an ACK/CTS so responses get priority. The NAV (Network Allocation Vector) is a "virtual carrier sense" timer set from the duration field in RTS/CTS frames.

Very important modern note

Modern switched Ethernet is full-duplex, so collisions don't occur on a dedicated switch link. CSMA/CD is mainly a historical/legacy concept today, but it remains important for interviews and for understanding Ethernet.

3.7Hidden terminal problem and RTS/CTS

A and C cannot hear each other, but both can reach B. A thinks "channel is free", C thinks "channel is free", both transmit to B → collision at B.

Wi-Fi can use RTS (Request To Send) and CTS (Clear To Send). Other nearby devices that hear the CTS stay silent for the announced duration.

+ Added Exposed terminal problem: the opposite case. B is sending to A; C hears B and wrongly stays silent, even though C's transmission to D would not interfere at A. Capacity is wasted.

4.1Error detection vs error correction

When data travels through a network, bits can get corrupted: sender sends 10110101, receiver gets 10100101.

Detection

Receiver knows "something is wrong", but not what the correct data was. Fix = ask again (retransmission).

Correction

Receiver knows something is wrong and can recover the correct data (forward error correction, FEC).

+ Added Single-bit error: one bit flipped. Burst error: several consecutive bits corrupted (length = first to last corrupted bit). Bursts are more common in real links, which is why CRC matters.

4.2Parity bit

The simplest error detection technique: add one extra bit so the number of 1s is even (even parity) or odd (odd parity).

Example: data 1011001 has four 1s. With even parity, append 0 → 10110010, total still even.

Problem

Parity detects any odd number of bit errors, but if two bits flip the count stays even and the error is missed. + Added 2-D parity (row + column parity) can detect more patterns and even correct a single-bit error.

4.3Checksum

Divide data into fixed-size words (16-bit for the Internet checksum)Add them with 1's complement arithmetic (wrap carries around)Complement the result → checksumReceiver adds everything including checksum → all 1s (complement = 0) means OK

If the result doesn't match: error detected. Checksum is for detection, not correction. + Added The 16-bit Internet checksum is used in the IPv4 header, TCP, UDP and ICMP. It is weaker than CRC (misses reordered words, for example) but cheap in software.

4.4CRC: Cyclic Redundancy Check

Very important for placements. CRC uses polynomial (modulo-2) division, which is just XOR without carries.

Sender

  1. Generator has degree r (r+1 bits)
  2. Append r zeros to the data
  3. Divide by the generator using XOR
  4. Remainder (r bits) = CRC
  5. Transmit data + CRC

Receiver

  1. Divide received data + CRC by the same generator
  2. Remainder = 0 → likely no error
  3. Remainder ≠ 0 → error

Worked example: data 101101, generator 1101 (degree 3). Append 3 zeros → 101101000, divide → remainder 010. Transmit 101101010. Try your own below; every XOR step is shown.

Why CRC is popular: it detects all single-bit errors, all double-bit errors (with a good generator), all odd numbers of errors (if the generator has factor x+1), and all burst errors of length ≤ r. Ethernet's FCS is CRC-32.

4.5Hamming code: error correction

Hamming code can detect and correct certain bit errors. Basic Hamming code corrects 1-bit errors and (with an extra overall parity bit, SECDED) detects 2-bit errors.

Parity bits sit at positions that are powers of 2: 1, 2, 4, 8, 16… For Hamming(7,4): P1 P2 D1 P4 D2 D3 D4.

  • P1 checks positions with bit 0 set: 1, 3, 5, 7
  • P2 checks positions with bit 1 set: 2, 3, 6, 7
  • P4 checks positions with bit 2 set: 4, 5, 6, 7

At the receiver, recomputing the checks gives a syndrome. The syndrome, read as a binary number, is the position of the wrong bit. Example: syndrome = 101₂ = 5 → bit 5 is wrong → flip bit 5. Encode 4 bits below, then click any bit to corrupt it.

Formulas + Added Parity bits r for m data bits: 2^r ≥ m + r + 1 To detect d errors: d_min ≥ d + 1 To correct t errors: d_min ≥ 2t + 1

Hamming distance = number of positions where two codewords differ (XOR, count 1s). Example m = 7 → r = 4 (2⁴ = 16 ≥ 12).
